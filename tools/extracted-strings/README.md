# Extracted Stardew Valley strings

Generated by `../XnbStringTool` from the actual game install. Not redistributed
anywhere: this is local reference data for the mod's translation feature and the source
text for `../segment-data`, and it can be regenerated at any time.

| Folder | Holds | From `Content/` |
|---|---|---|
| `en/`, `zh/` | every `Strings/*` table that is a plain `Dictionary<string,string>` | `Strings/<name>.xnb`, `Strings/<name>.zh-CN.xnb` |
| `data-en/`, `data-zh/` | the `Data/*` tables `segtool.py`'s `DATA_TABLES` reads | `Data/<name>[.zh-CN].xnb` |
| `content-en/`, `content-zh/` | per-NPC / per-location families (dialogue, events, festivals, TV, schedules), mirroring their path | `<path>[.zh-CN].xnb` |
| `ja/`, `data-ja/`, `content-ja/` | the Japanese originals, from before the fork | `.ja-JP.xnb` |

Every JSON file is `{ typeReaders, wasCompressed, entries }`. `Strings/credits.xnb` is
excluded, because it's a `List<string>` rather than a dictionary and has no hover
target.

The `ja` folders are kept only because `../ModLogic.Tests` (`DataTextShapesTests`,
`RealStringTableTests`) still reads them. Delete them once those tests are moved to zh
(see "Chinese migration" in `TODOs.md`).

## Regenerating the zh folders

The zh folders were extracted on 2026-09-28 from game 1.6.15, one file for each file in
the ja folders (178 tables). Every localised asset the game ships in zh-CN that isn't
here is a font or a texture, which `segtool.py audit` confirms. To redo it:

```sh
cd tools/XnbStringTool && dotnet build -c Release && cd ../extracted-strings
bash -c '
C="$HOME/Library/Application Support/Steam/steamapps/common/Stardew Valley/Contents/Resources/Content"
xnb() { [ -f "$1" ] && dotnet ../XnbStringTool/bin/Release/net8.0/XnbStringTool.dll read "$1" "$2"; }  # skips en-only files (Data/Events/IslandFarmHouse is empty and unlocalised)
for f in en/*.json;      do n=$(basename "$f" .json); xnb "$C/Strings/$n.zh-CN.xnb" "zh/$n.json"; done
for f in data-en/*.json; do n=$(basename "$f" .json); xnb "$C/Data/$n.zh-CN.xnb" "data-zh/$n.json"; done
find content-en -name "*.json" | while read -r f; do r=${f#content-en/}; r=${r%.json}; xnb "$C/$r.zh-CN.xnb" "content-zh/$r.json"; done'
```

After a game update, run `python3 ../segment-data/segtool.py audit` to find any new
asset family, then extract the English too with the same loop on the unsuffixed files.

## Known data quirks

- `Strings/UI` has 886 keys in `ja` but 883 in `zh`, so key sets can differ slightly
  between locales. `segtool.py` pairs English by key and leaves it empty when there's
  no match.
- 35 zh entries that need authoring have no official English counterpart. The
  worklist shows an empty third column for them.
