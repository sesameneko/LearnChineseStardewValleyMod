M2 segmentation data — every table is now authored
--------------------------------------------------
All 9,039 in-game strings across every Strings/* and Content/Data table have
hand-authored segment data; 11 keys are deliberately skipped (event command
scripts, which the game never draws as a single string). `segtool.py status`
shows pending=0 everywhere and `segtool.py validate` passes.

Still open here: the Objects item-name split below, and Achievements /
SecretNotes, which tools/XnbStringTool still can't read.

The pipeline, for future re-passes (tools/segment-data/segtool.py):

  python3 tools/segment-data/segtool.py status          # coverage per table
  python3 tools/segment-data/segtool.py batch Tools 50  # next worklist, as TSV
  ...author a .tsv...
  python3 tools/segment-data/segtool.py merge Tools batch.tsv
  python3 tools/segment-data/segtool.py validate

Authoring format is one entry per line, tab-separated:
  key <TAB> english <TAB> text¦reading¦gloss‖text¦reading¦gloss‖...
merge rejects any line whose segment texts don't concatenate back to the
source string exactly, so bad data can't reach the mod.

Output goes to tools/extracted-strings/literal-translations/<Table>.json —
that folder is the tracked source of truth; assets/segments/ is gitignored and
generated from it by the csproj's CopySegmentData target.

Status: all tables complete (9,039 authored, 11 skipped, 0 pending).

Objects item names — split the multi-word ones
----------------------------------------------
tools/segment-data/migrate_names.py has already converted Objects_Name.json from
the old flat "key": "English (reading)" reference format into the segment format,
so all 756 item names now load and hover with a real reading and gloss instead of
falling back to the character-class heuristic.

The migration treats each name as ONE segment covering the whole string. That is
correct for a single-word name (木材 = mokuzai = Timber) and wrong for a
multi-word one: 木の柵 should be 木 / の / 柵, アメシストの指輪 should be
アメシスト / の / 指輪.

Roughly 395 of the 756 names span more than one script run and so definitely need
splitting; the other ~361 are single-run and mostly fine as they stand (though an
unbroken kanji run like 高機能テレビリモコン can still need a split). Do this pass
the same way as any other table -- the entries are already in the right shape, so
it is editing segments arrays rather than translating from scratch, and
segtool.py validate still enforces that the segments reproduce the source string.

Priority: this is the main remaining segmentation work.
